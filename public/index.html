Cost Allocation /api/allocation

Month x host x country x product feature, with credits derived from usage at your contracted rates. Credits that cannot be attributed to a host (compute, deploys, forms, AI) appear in the reconciliation as an unallocated remainder, not spread across hosts. Dollars are blended (share of credits x invoiced USD), not line-item prices. Allocation months are capped at 24 per request.

API Quick Reference

Authentication

Direct calls to the usage API use Authorization: Bearer <CUSTOMER_API_KEY>. This dashboard never sees that key: the browser calls /api/* on this site and a server-side proxy attaches it. If the dashboard operator set a DASHBOARD_ACCESS_KEY, enter it in the field above; it is sent as a bearer token to the proxy only.

GET /v1/usage?start=YYYY-MM-DD&end=YYYY-MM-DD&granularity=month|day

start is inclusive, end is exclusive. Max span about 5 years. Returns usage by period / account / site / accounting / owner, members, geo, functions, credits, all wrapped in a meta envelope.

curl -s -H "Authorization: Bearer $CUSTOMER_API_KEY" \ "$USAGE_API_URL/v1/usage?start=2026-01-01&end=2026-07-01&granularity=month"

GET /v1/allocation?start=&end=&format=csv|json

The Finance driver table: month x host x country x product feature with usage, credits and blended dollars. CSV by default. Read the reconciliation block before trusting a total: unattributable credits are reported as a remainder, never spread.

curl -s -H "Authorization: Bearer $CUSTOMER_API_KEY" \ "$USAGE_API_URL/v1/allocation?start=2026-01-01&end=2026-07-01" -o allocation.csv

Reading meta

  • meta.coverage shows the seam between live sources (last ~90 days) and stored monthly snapshots. Anything outside both is absent, not zero.
  • meta.freshness: credits lag about 48 hours; the current period is always provisional.
  • meta.warnings lists sections that degraded (a source failed, or history is not configured). A response with warnings still renders; the flagged sections may be empty.
  • Geo and per-function detail have 1 to 4 day source windows. For older ranges they come from daily snapshots that only accumulate going forward.

Also available

  • GET /v1/health: liveness, no auth.
  • GET /report: server-rendered HTML report over the same data (key entered in the form, useful without any tooling).

Full documentation, including response schemas, lives in this project's README.
